Artipin MVP 계획 개요

AI가 만든 HTML·이미지를 링크 하나로 공유하고, 화면 위치에 핀 댓글을 다는 서비스 · 사내 MVP · 2026-10-16

한 줄 정의. 파일을 올리면 링크가 생기고, 링크를 받은 사람은 로그인 없이 화면 위치에 핀으로 댓글을 단다. 올린 사람은 댓글을 확인하고 해결 처리한다.
전체 결정 기록: docs/designs/artipin-mvp.md · HTML 격리 상세: docs/html-sandbox-design.html

1. 왜 만드는가

지금은 AI 산출물을 캡처해서 메신저로 보내고, 말로 위치를 설명하며 피드백을 받는다. 위치를 말로 지정해야 하고, 인터랙티브 HTML은 캡처하면 상호작용이 사라진다.

약한 지점: 수요 증거는 가설 단계다. 본인의 불편에서 출발했고, 댓글 작성자는 직군("개발자, 기획자, 고객, 경영진")뿐이며 이름이 없다. 경쟁 제품(coeditHTML, HaveTML, Artifact Share 등)이 이미 같은 기능을 제공한다는 점은 ChatGPT 리포트 기준이며 직접 검증하지 않았다. 이슈 #1이 이 약점을 추적한다.

데이터 모델

테이블주요 컬럼
ownersprovider, provider_account_id(유일 쌍), email(표시용), name
filesowner, kind(image|html), title, storage_path, size, share_token, created_at, deleted_at
commentsfile, parent, author_name, visitor_id, is_owner, body, anchor(JSON), resolved_at, created_at
viewsfile, visitor_id, first_seen_at (복합 PK)

삭제는 파일 본문만 제거하고 deleted_at을 기록한다. 행은 남겨 관찰 지표가 사라지지 않는다.

5. 사업화 판단 지표

지표정의 (SQL로 조회)알려진 오차
(a) 전달소유자 외 views가 1건 이상인 파일 수소유자의 로그아웃 상태 열람, 링크 미리보기 크롤러가 섞일 수 있음
(b) 댓글is_owner=0 댓글이 1건 이상인 파일 수—
(c) 재업로드파일을 2개 이상(삭제 포함) 올린 소유자 수같은 사람이 다른 제공자로 로그인하면 별도 소유자로 집계(과소·과대 모두 가능)

판단 임계값은 첫 2주 데이터를 본 뒤 정한다.

7. 검증 방식

  • 자동화 테스트 스위트는 만들지 않는다. 각 이슈의 수용 기준을 수동으로 확인한다.
  • 재현된 결함이 생기면 그 결함에 대해서만 테스트를 추가한다.
  • 예외: 이슈 #8에서 적대적 HTML 샘플 1개로 격리를 한 번 확인한다.

8. 열린 질문

  1. 해결: 개인 계정 간편 인증(Google·Microsoft·GitHub).
  2. 배포가 사내망 전용인가? (외부 리소스 허용 근거)
  3. 사내 첫 댓글 작성자 3명은 누구인가? — 이슈 #1.
  4. 인터랙션 보존(HTML)이 실제로 필요한 사례가 있는가? 없다면 이미지만으로 충분했을 수 있다. — 이슈 #1.
  5. 캡처 방식의 번거로움은 얼마인가(한 번에 몇 분, 주 몇 회)? — 이슈 #1.
  6. CSP 기본값을 샘플 확인 뒤 좁힐지, 샌드박스 제약으로 깨지는 샘플이 얼마나 되는지. — 이슈 #8.
  7. 사업화 판단 임계값. — 첫 2주 데이터 이후.
