HTML 격리·앵커링 명세

업로드된 독립형 HTML을 안전하게 실행하고, 그 위에 핀 댓글을 붙이는 방법 · Artipin MVP · 이슈 #6, #8, #39 구현 기준

핵심 규칙 세 가지.
1) 업로드 HTML은 CONTENT_HOST에서만 서빙하고(zip 사이트는 /c/{token}/{path}로 디렉터리 안 파일을 서빙한다) iframe은 sandbox="allow-scripts"만 준다 (allow-same-origin 금지).
2) 부모와 iframe 사이 postMessage 채널은 하나뿐이고, 받는 쪽은 항상 출처(event.source)와 내용(스키마)을 둘 다 검사한다. 브리지가 보내는 pointer는 부모가 검사·빈도 제한한 뒤에만 서버로 보낸다.
3) 앵커 값은 어디서 오든 신뢰하지 않는다. 브라우저 쪽과 API 쪽에서 같은 스키마로 검증하고, 값은 텍스트로만 렌더한다.

1. 위협과 대응

위협대응남는 위험
업로드 HTML이 앱 쿠키·세션을 읽음iframe sandbox에 allow-same-origin 없음 → 불투명 출처. 콘텐츠를 직접 열어도 CSP sandbox 헤더가 같은 효과. 세션 쿠키는 Domain 없는 호스트 전용없음(앱 데이터 기준)
업로드 HTML이 앱 API를 호출불투명 출처 + CSP connect-src 'none'(콘텐츠 응답) + 앱 API는 세션 쿠키 필요없음
피싱 폼 제출CSP form-action 'none', sandbox에 allow-forms 없음링크 클릭 유도(allow-popups 없음으로 새 창은 막힘)
외부 리소스 경유 유출·방문자 추적기본 정책은 외부 스크립트·이미지·스타일을 허용(CDN 차트 라이브러리 때문)감수. 업로더는 Google·Microsoft·GitHub 계정이 있는 누구나다(도메인 제한 없음). 앱 데이터는 불투명 출처로 보호됨. 배포가 사내망 전용인지 미확인(열린 질문). 샘플 확인 후 좁힘
적대적 HTML이 postMessage 위조부모가 종류 허용 목록·범위·길이 검사, 값은 텍스트로만 렌더엉뚱한 위치의 핀(최악)
적대적 HTML이 pointer 메시지 위조·폭주부모가 event.source·스키마(anchor-picked와 같은 selector 1~500자, relX·relY 0~1) 검사 후 마지막 값만 들고 100ms에 1회만 POST. 업로드 HTML은 connect-src 'none'·불투명 출처라 포인터 API를 직접 호출할 수 없다엉뚱한 위치의 커서(최악). 초당 수천 건 메시지는 부모의 검사 함수까지는 실행된다(서버로는 ≤10건/초)
링크 보유자가 포인터 API를 직접 호출해 다른 방문자 화면에 커서 폭주서버가 댓글 API와 같은 앵커 스키마(image·pdf·html)로 검증(위반 400), 파일 종류 일치 확인. 서버측 속도 제한은 두지 않는다 — 댓글 API도 없고, 영향은 같은 파일을 보는 사람의 화면 점 표시에 그친다화면 소음. 관찰되면 그때 방문자별 제한을 추가
실시간 커서로 다른 방문자의 위치·활동이 업로드 HTML에 노출HTML 파일은 부모가 다른 방문자의 커서를 render-pointers로 iframe에 넘긴다(아래 "실시간 커서 노출 정보"). 이름·쿠키 값·이메일·IP는 싣지 않고 파일별 불투명 id만 쓴다업로드 HTML이 (외부 리소스 허용 정책에 따라) 같은 파일을 보는 다른 방문자들의 위치·움직임·활동 시점을 읽어 외부로 보낼 수 있다. 감수
API 직접 호출로 임의 anchor 저장댓글 생성 API가 같은 스키마 검증, 위반은 400없음
토큰 추측128비트 랜덤 토큰, 추측 가능한 id 경로 없음없음
같은 공유 토큰 보유자가 ?v={no}로 이전 버전 본문 열람제한 없음 — 버전은 같은 토큰의 일부(이슈 #28 설계)교체한 이전 본문도 링크 보유자에게 보인다. 끊으려면 파일 삭제(모든 버전 본문 삭제)
업로드 PDF가 서버 poppler 취약점을 노림업로드 때 pdftoppm으로 1회만 변환(조회 경로에서는 파서가 돌지 않음), SIGKILL 타임아웃·페이지 상한(-l)·-scale-to 픽셀 상한, 자식 프로세스 env는 PATH만, 컨테이너는 비루트(node)poppler 취약점이 있으면 컨테이너 node 권한으로 /data(DB·업로드)에 닿을 수 있다. 동시 변환 수 제한은 없다
zip slip(..·절대 경로·드라이브 문자)풀기 규칙을 하나라도 어기면 업로드 전체를 거절한다. 서빙 때도 세그먼트(..·.·빈 값·/·\·NUL)를 거절하고 resolve 결과가 사이트 디렉터리 안인지 접두사로 검사한다없음
zip 안의 심볼릭 링크 항목중앙 디렉터리 외부 속성으로 판정해 거절한다(__MACOSX/ 등 건너뛸 항목이라도 링크면 거절)없음
압축 폭탄실제 해제 바이트와 항목 수를 풀면서 세어 20MB·300개에서 멈추고 임시 디렉터리를 지운다. 헤더의 선언 크기는 믿지 않는다동시 업로드 수 제한은 없다(PDF 행과 같은 수준). 원본 zip 20MB는 메모리에 올라간다
하위 HTML·SVG 안의 스크립트본문을 서빙하는 site 응답 전부에 CSP sandbox·nosniff를 붙이고, 확장자 표 밖 파일은 업로드 거절·서빙 404없음(앱 데이터 기준)
앱 화면을 다른 사이트가 프레임으로 삽입APP_HOST 응답에 frame-ancestors 'none'없음
MIME 스니핑·인코딩 혼동nosniff, Content-Type 고정(HTML은 UTF-8만 업로드 허용), 이미지는 매직바이트 판정값없음

2. 호스트와 응답

CONTENT_HOST 응답 (/c/{share_token})

HTML
  Content-Type: text/html; charset=utf-8
  Content-Security-Policy: sandbox allow-scripts; connect-src 'none'; form-action 'none'; frame-ancestors <APP_HOST>
  X-Content-Type-Options: nosniff

이미지
  Content-Type: image/png | image/jpeg | image/webp   (매직바이트 검증 결과)
  X-Content-Type-Options: nosniff

PDF
  페이지 PNG를 이미지와 같은 헤더로 서빙: /c/{share_token}?p={n}  (p 없으면 1, ?v=와 함께 쓰면 그 버전의 페이지)
  없는 페이지·숫자가 아닌 p: 404

/c/{share_token}/{path}   (zip 사이트, kind=site)
  Content-Type: 확장자 표(html·htm·css·js·mjs·json·png·jpg·jpeg·gif·webp·svg·ico·woff·woff2·ttf·otf). 표 밖 확장자는 404
  본문을 서빙하는 응답 전부(하위 HTML·SVG 포함):
    Content-Security-Policy: sandbox allow-scripts; connect-src 'none'; form-action 'none'; frame-ancestors <APP_HOST>
    X-Content-Type-Options: nosniff
    Cache-Control: no-cache
    Access-Control-Allow-Origin: *
  브리지는 .html·.htm 응답에만 주입한다.
  경로 탈출(.. 세그먼트, 사이트 디렉터리 밖으로 풀리는 경로)·없는 파일·디렉터리: 404
  진입은 /c/{share_token}/index.html 이고, /c/{share_token} 은 그쪽으로 302 (Location만 있는 본문 없는 응답)
  만료·삭제된 토큰은 하위 경로까지 404. site의 ?v=는 받지 않는다(404)

/c/{share_token}?v={no}
  해당 버전 본문. 위 헤더는 그대로.
  없는 버전·숫자가 아닌 v: 404

없는 토큰·삭제된 파일: 404 (두 호스트 모두)
  • site 응답의 Access-Control-Allow-Origin: *는 sandbox(불투명 출처) 문서의 type="module" 스크립트·@font-face 요청이 CORS 모드라 필요하다. 토큰을 알면 이미 본문을 읽을 수 있어 새로 노출되는 것은 없고, 앱 API 접근은 connect-src 'none'을 유지해 막는다.
  • default-src를 두지 않는다. 외부 스크립트·이미지·스타일은 허용한다. 좁힐지는 샘플 확인 뒤 결정한다.
  • CONTENT_HOST는 /c/*만 응답한다. /s/*, /api/*, 로그인 경로는 404.
  • APP_HOST는 업로드 파일 본문을 직접 서빙하지 않는다.
  • .md·.json은 업로드(교체 포함) 때 HTML로 변환해 HTML과 같은 경로로 서빙한다. 새니타이즈하지 않는다. 마크다운 속 raw HTML·스크립트도 업로드 HTML과 같은 CSP sandbox·별도 origin에서 실행되어 위협이 같기 때문이다(#31).
  • 로컬 개발: app.localhost, content.localhost (*.localhost는 로컬로 해석된다).

3. 앵커

이미지:  { "kind": "image", "x": 0.45, "y": 0.32 }                      // 이미지 크기 대비 0~1
PDF:     { "kind": "pdf",   "page": 3, "x": 0.45, "y": 0.32 }                  // page는 1부터, x·y는 그 페이지 이미지 대비 0~1
HTML:    { "kind": "html",  "selector": "main > section:nth-of-type(2) > canvas", "relX": 0.62, "relY": 0.31 }
답글:    anchor = null  (답글은 1단계, 부모 댓글의 핀을 따름)

선택자 만들기 (브리지, 클릭 시)

  1. 클릭된 요소에서 시작해 id가 있는 가장 가까운 조상까지 올라간다(없으면 body까지).
  2. 각 단계는 tag:nth-of-type(n), id가 있으면 #id로 끊는다.
  3. relX = (clientX − rect.left) / rect.width, relY도 같은 방식. 0~1로 자른다.

핀 그리기

  1. 부모가 render-pins로 댓글 목록(번호, selector, relX, relY, quote?, resolved)을 보낸다. quote(드래그로 고른 문장)가 있으면 selector 요소 안의 첫 일치를 CSS Custom Highlight API로 칠한다(DOM 불변). 찾지 못하면 핀만 남는다.
  2. 브리지는 댓글마다 try { document.querySelector(selector) } catch로 요소를 찾는다. 실패하면 그 댓글만 "핀 없음"으로 두고 나머지는 계속 그린다.
  3. 찾으면 getBoundingClientRect()와 스크롤 위치로 절대 좌표를 계산해 오버레이에 그린다. 스크롤·리사이즈 때 다시 계산한다.
  4. 핀 없는 댓글도 댓글 목록에는 항상 보인다. 탭·필터 상태 복원은 하지 않는다(MVP 범위 밖).

4. postMessage 프로토콜

방향typepayload수신측 검사
브리지 → 부모bridge-ready{ path } (iframe 문서의 location.pathname). 로드 후 부모가 hello를 보내면 다시 보낸다부모: event.source === iframe.contentWindow, path는 문자열·2000자 이하. zip 사이트에서 진입 페이지(/c/{token}/index.html)가 아니면 핀을 끈다
부모 → 브리지hello없음브리지: event.source === window.parent. 응답으로 bridge-ready를 다시 보낸다
부모 → 브리지mode{ mode: "browse" | "comment" }브리지: event.source === window.parent, mode 허용 목록
브리지 → 부모anchor-picked{ selector, relX, relY, quote? }부모: event.source === iframe.contentWindow, selector는 문자열·500자 이하, relX·relY는 0~1 숫자, quote는 있으면 1~300자 문자열
부모 → 브리지render-pins[{ id, n, selector, relX, relY, quote?, resolved }]브리지: 출처 확인, 배열·타입 확인
브리지 → 부모pointer{ selector, relX, relY }부모: event.source === iframe.contentWindow, selector 문자열 1~500자, relX·relY 0~1 숫자, 그 외 키 무시. 통과한 값은 100ms 단위로 마지막 것만 서버로 보낸다
부모 → 브리지render-pointers[{ id, selector, relX, relY }]브리지: 출처 확인, 배열·타입 확인(render-pins와 같은 방식), 못 찾는 selector는 그 점만 생략
  • iframe이 불투명 출처라 targetOrigin을 지정할 수 없다. 그래서 "*"로 보내되 수신측이 출처와 내용을 모두 검사한다.
  • 알 수 없는 type은 무시한다.
  • 부모는 payload 값을 DOM에 넣을 때 textContent만 쓴다. HTML로 해석하지 않는다.
  • 브리지는 pointer를 100ms에 최대 1회 보낸다. 이것은 성능을 위한 것이고, 빈도의 보안 경계는 부모다.

실시간 커서 노출 정보

  • 내보내는 것: 파일별 불투명 id(pid — 서버가 프로세스 시작 시 만든 무작위 salt, 파일 id, 방문자 쿠키를 SHA-256으로 해시해 12자로 자른 값), 앵커 종류와 위치(HTML: selector·relX·relY / 이미지: x·y / PDF: page·x·y).
  • 받는 사람: 그 파일 링크로 뷰어를 열어 둔 모든 사람(소유자·익명 구분 없음). "지금 보는 중"이 2명 이상인 동안만 연결한다. 자기 커서는 받지 않는다(같은 방문자 쿠키 제외).
  • 업로드 HTML에 새로 노출되는 것: HTML 파일이면 부모가 다른 방문자의 커서를 render-pointers로 iframe 안에 넘기므로 업로드 HTML(외부 리소스 포함)도 그 값을 읽고 외부로 보낼 수 있다. 지금까지 업로드 HTML이 읽던 포인터는 자기 방문자 본인의 것뿐이었다. 이 기능으로 다른 방문자들의 위치·움직임·활동 시점과 pid가 새로 노출된다. 이미지·PDF는 업로드 파일이 코드를 실행하지 않아 해당 없다.
  • 내보내지 않는 것: artipin_visitor 쿠키 값(답글·댓글 삭제 권한의 근거), 이름, 이메일, IP, 소유자 여부. pid는 파일마다·서버 재시작마다 달라 다른 파일과 연결할 수 없다.
  • 경로: POST /api/s/{token}/pointer(송신), GET /api/s/{token}/pointer(SSE 수신). 둘 다 APP_HOST 전용이라 CONTENT_HOST의 업로드 HTML은 직접 닿지 않는다. 만료·삭제·없는 토큰은 404.
  • 단일 인스턴스 전제: 구독자 집합은 프로세스 메모리다. 다중 인스턴스로 가면 다른 인스턴스의 커서가 안 보인다. 구독은 토큰 단위라 링크를 새로 만들면 옛 링크로 열린 연결에는 커서가 가지 않는다.

검증 규칙 (브라우저 · API 공통)

  • kind ∈ {image, html, pdf}. 파일 종류와 일치해야 한다. zip 사이트(site) 파일은 html 앵커를 쓴다.
  • 좌표는 0~1 숫자. 문자열·NaN·범위 밖은 거부.
  • selector는 문자열, 500자 이하. 문법 검사는 브리지에서 예외 처리로 대신한다.
  • quote는 선택 사항, 있으면 문자열 1~300자.
  • author_name 50자, body 2000자 이하.
  • 위반하면 API는 400을 반환한다.

5. 브리지 모드와 알려진 한계

  • 탐색 모드: 브리지는 아무것도 가로채지 않는다. 원본 HTML이 그대로 동작한다. 다만 커서 공유를 위해 mousemove를 수동(passive)으로 청취해 위치만 읽는다. preventDefault는 하지 않는다.
  • 댓글 모드: 브리지가 캡처 단계에서 클릭을 가로채고(preventDefault) 선택자를 계산해 anchor-picked를 보낸다. 드래그 선택이 있으면 mouseup에서 공통 조상 요소의 선택자와 인용문(quote)을 보내고, 뒤따르는 click은 핀을 만들지 않는다.
  • 샌드박스 제약: localStorage·sessionStorage·document.cookie 접근이 예외를 던지고, alert·폼 제출·새 창 링크가 막힌다. 로드 시 localStorage를 쓰는 HTML은 깨질 수 있다. 저장소 대체 shim은 넣지 않고 샘플로 얼마나 깨지는지 확인한다.
  • 업로드 HTML의 자체 CSP: <meta http-equiv="Content-Security-Policy">가 인라인 스크립트를 막으면 브리지가 실행되지 않는다. 이 경우 뷰어는 "이 파일은 핀 댓글을 지원하지 않을 수 있습니다"를 표시하고 목록 댓글만 허용한다.
  • zip 사이트(진입 페이지만 핀): iframe 안에서 다른 페이지로 이동하면 뷰어가 "이 페이지는 핀 댓글 미지원"을 표시하고 댓글 모드를 끈다(앵커에 path를 두지 않는다). 진입 페이지로 돌아오면 핀이 다시 보인다.
  • zip 사이트의 한계: 루트 절대 경로(/assets/…)로 만든 빌드는 깨진다(base: "./" 권장, 경로 재작성은 하지 않는다). connect-src 'none'이라 같은 사이트의 JSON fetch도 막힌다. 하위 폴더 디렉터리 인덱스와 SPA 폴백은 없다. 이전 버전 미리보기·비교는 제공하지 않고(상대 자산이 현재 버전과 섞인다) 되돌리기만 된다. zip 안의 __MACOSX/·.DS_Store는 무시한다.
  • 핀 스타일: 핀이 페이지 DOM 안에 그려지므로 페이지 CSS가 가리거나 바꿀 수 있다. 그런 사례가 확인되면 Shadow DOM으로 격리한다(미리 넣지 않는다).
  • 선택자가 깨지는 경우: 동적으로 바뀌는 페이지는 selector가 안 맞을 수 있다. 핀은 숨기고 댓글 목록에는 남긴다.

6. 격리 확인 체크리스트 (이슈 #8, 1회)

적대적 샘플 HTML 한 개를 올리고 뷰어에서 열어 아래가 모두 실패하거나 걸러지는지 확인한다. 결과는 이슈 #8에 기록한다. 자동화 테스트로 만들지 않는다.
